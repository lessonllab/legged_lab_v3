## 本次调整

- 按机器人数量分配：25% 平地、35% 上楼梯、20% 下楼梯、20% 其他崎岖地形，取整误差不超过一个环境。原来的 10×10 地形网格保留；通过显式分配机器人的地形列调整练习比例，而不是删掉某类地形。
- 机器人仍从中央平台生成，目标在 +X 外围平台。因此 `pyramid_stairs_inv` 是向外上楼，`pyramid_stairs` 是向外下楼。上下楼独立统计、独立升降级。
- 楼梯第 1–9 行的单阶高度固定为 8、10、12、14、16、18、20、21.5、23 厘米；第 0 行保留平地。阶宽、中央平台和其他地形几何参数不改。
- 首次从 balanced 迁移时，仅将楼梯设置为 10 厘米、低速档。平地已有速度档与其他崎岖地形等级保留。后续正常重置，80% 楼梯环境练当前阶段，20% 练前一档高度（最低 8 厘米）。
- 楼梯低速档 0.35–0.55 m/s，高速档 0.55–0.75 m/s。每个高度先练低速，通过后练高速，再增加高度并返回低速。平地速度课程仍保留最高 1.2–2.0 m/s 档。
- 上、下楼各积累至少 50 次当前阶段的完整尝试：通过率 >80% 推进一阶段，<50% 回退一阶段，其余保持。完成窗口后清空统计，新窗口忽略旧窗口开始的回合。简单高度复习、手动目标、初始化重置均不用于推动当前阶段。
- 楼梯每回合固定一个目标和速度，不在途中重新采样站立指令。完成判定使用最近 1 秒（当前 50 帧）：至少 90% 的帧满足目标附近、双脚进入终点外围平台及直立等几何条件，平均水平速度大小 <0.2 m/s，且达标的当前帧也满足几何条件。速度取每帧向量的模再平均，来回高速运动不会相互抵消。这个阈值只约束终点停稳，不限制途中速度。
- 窗口达标后记住本回合已完成，但回合结束时若失败终止、离开终点或姿态不合格，仍不算通过。初始化、手动目标和重置均清空短窗口。站在出生平台、从终点高速冲过、脚仍在较低台阶、到达后又摔倒都不能靠短暂接近伪造通过。
- 原来每一帧都必须角速度 <0.3 rad/s 的条件只作为严格停稳质量指标，不再阻止升级。到达终点、窗口停稳、严格停稳、最终安全完成分别记录。
- 保留完整的 30 段参考、采样权重、镜像、时序、AMP 系数 0.5、全部奖励与终止配置、深度相机和网络输入。第一轮不增加抬脚奖励、不调整风格权重。
- 专项任务关闭首回合随机截短，避免没有完整爬楼时间的样本污染通过率；原任务保持原行为。

课程 checkpoint 版本为 4，显式保存机器人分组、地形列、楼梯高度/速度阶段、窗口计数和 epoch。支持从 balanced 版本 2、旧专项版本 3 迁移，以及版本 4 原规模续训和缩小环境数量重放。从版本 3 迁移时保留网络、优化器、地形等级、主练高度/速度阶段、平地速度档，清空旧判定的 attempts/wins/last_rate/epoch；否则旧的假阴性会污染新窗口。从版本 4 恢复时完整保留新课程统计。单回合短窗口随物理环境重置，不跨回合或恢复边界保留。

## 开始专项续训

先在当前旧训练终端按 Ctrl+C，等进程退出。以下命令追加 3000 轮，训练输出进入新的 `logs/rsl_rl/g1_amp_stairs_specialist/`，原 checkpoint 不覆盖。

```bash
cd /home/ljc/legged_lab_v3
ISAACLAB_PYTHON=/home/ljc/isaaclab/bin/python \
bash scripts/run_with_rsl5.sh scripts/rsl_rl/train.py \
  --task LeggedLab-Isaac-AMP-Stairs-G1-v0 \
  --viz none --device cuda:0 --num_envs 2048 \
  --max_iterations 3000 --seed 42 --run_name stairs_window_style05 \
  --resume \
  --load_run /home/ljc/legged_lab_v3/logs/rsl_rl/g1_amp_stairs_specialist/2026-09-14_21-21-39_stairs_preserve_flat_style05 \
  --checkpoint model_23600.pt agent.device=cuda:0
```

以后恢复本专项训练时，仍使用 Stairs 任务，但把 `--load_run` 和 `--checkpoint` 改为新专项运行目录和它保存的模型；不要再次指向旧 balanced 模型，否则会重新初始化楼梯课程。

## 看哪些指标

TensorBoard 的 `Curriculum/terrain_levels/` 下：

- `ascent/height_cm`、`descent/height_cm`：当前主练高度，直观反映课程难度。
- `ascent/speed_phase`、`descent/speed_phase`：0 为低速，1 为高速。
- `*/window_pass_rate`：最近一个完成窗口的通过率；-1 表示尚未积累首个窗口，不是负成功率。
- `*/window_attempts`：当前窗口已积累的有效尝试数。
- `*/batch_successes` 和 `*/batch_attempts`：重置批次内实际通过与尝试数量，包含复习高度。绘图时需要分别求和后相除，不能把日志批次均值直接当总成功率。
- `*/batch_failures`：同一批次因原有失败终止条件结束的楼梯尝试数，用来区分摔倒等失败与存活但未完成。
- `*/batch_traversed`：曾满足终点平台和姿态条件的数量；`*/batch_window_settled`：曾满足新窗口停稳要求的数量；`*/batch_strict_settled`：曾满足原严格角速度停稳要求的数量。三者都是回合中曾经达到的诊断计数，不能替代最终的 `batch_successes`。
- `flat_speed_cap_mean`、`flat_fast_fraction`：检查平地高速课程是否退化。

不同窗口有不同高度/速度阶段，比较通过率必须同时看对应阶段。从 balanced 首次迁移会回到 10 厘米；本次从旧专项版本 3 迁移会保留实际已有高度，不会重新回到 10 厘米。

## 验证与后续评估

自动检查覆盖实际阶高与上下楼方向、环境比例、奖励/参考/相机不变、成功判定排除冲过/低阶/倾倒/边缘、样本数与阈值边界、阶段迟滞、旧阶段与手动回合排除、旧模型迁移和缩小环境数恢复。

GPU 检查使用 64 环境验证加载、完整回合训练、保存及再次恢复；其结果只用于运行兼容性检查。正式续训后应固定高度、速度、种子和尝试次数，分别比较上下楼通过率，以及平地慢走/高速的速度跟踪、摔倒和步态；本次没有宣称通过率已经改善。

历史版本 3 兼容性验证：22 项课程测试通过；从 `model_21500.pt` 迁移后运行 48 轮，再恢复 2 轮。记录见 [validation.json](analysis/stair_specialist/validation.json)。后来固定模型对照证明含探索噪声的角速度会反复清空旧停稳计时，详见 [diagnosis_23200.md](analysis/stair_specialist/diagnosis_23200.md)。这些历史结果不作为版本 4 的验证结论。

版本 4 已通过 27 项课程测试（包括 GPU 设备映射）。固定 `model_23200.pt`、64 环境、2200 步，启用采样动作和 policy 观测噪声，在同一批轨迹上比较两个判定：上楼 45 次中旧规则 0 次、新规则 42 次通过；下楼 26 次中旧规则 0 次、新规则 24 次通过。该测试没有更新策略或课程，说明计分恢复了对实际完成的识别，不表示策略能力因改判定而提高，也不代表已学会高阶楼梯。原始结果见 [audit_window_23200.json](analysis/stair_specialist/audit_window_23200.json)。

另从正式专项 `model_23600.pt` 迁移到版本 4，以 64 环境更新 2 轮并保存，再从新 checkpoint 恢复更新 2 轮，均正常退出。高度/速度阶段和平地档位保留，旧完成统计清零，新版本可再次恢复。记录见 [validation_v4.json](analysis/stair_specialist/validation_v4.json)。正式续训使用 `model_23600.pt`，不使用这些小规模验证模型。
